# Двоичный формат BIDX, версии 1.0 и 1.1

Индекс — один двоичный файл. Текстовый TSV используется только для передачи
исходного корпуса, а не как поисковый индекс. Заголовки, URL и термы хранятся
внутри двоичных записей как UTF-8 без завершающего нуля. Все целые числа
беззнаковые, little-endian. Каждое число читается и записывается целиком в
поле фиксированного размера. Текущая реализация рассчитана на little-endian
платформы и читает и записывает байты целочисленных полей напрямую.
`static_assert` проверяет порядок байтов при компиляции. Размер и выравнивание
C++-структур на формат не влияют. Смещения считаются от начала файла.

Структуры записей объявлены в `index/include/index_format.hpp`:
`Header`, `Section`, `DocumentRecord`, `TermRecord`, `PostingRecord`,
`StatisticsRecord`, `IndexingRecord`. Каждая запись определяет `operator>>` для `std::istream`
и `operator<<` для `std::ostream`. Реализации находятся в `index/src/index_format.cpp`.
Длины строк вычисляются при записи и читаются перед содержимым.
Загрузчик читает документы и термы из отдельных потоков размером с секцию.

## Заголовок: 64 байта

| Смещение | Байты | Поле | Значение |
|---:|---:|---|---|
| 0 | 8 | Сигнатура | `42 49 44 58 0D 0A 1A 0A` (`BIDX`, CR, LF, SUB, LF) |
| 8 | 2 | Major | `1` |
| 10 | 2 | Minor | `0` без времени индексации, `1` с замером |
| 12 | 4 | Размер заголовка | `64` |
| 16 | 4 | Число секций | `4` или `5` с замером |
| 20 | 4 | Обязательные флаги | `0` |
| 24 | 8 | Число документов D | Размер прямого индекса |
| 32 | 8 | Число термов V | Размер словаря |
| 40 | 8 | Размер файла | Точное число байтов |
| 48 | 8 | Смещение каталога секций | `64` |
| 56 | 8 | Резерв | `0` |

Идентификатор документа — `uint32`, равный его позиции в прямом индексе,
начиная с нуля. Реализация ограничивает D числом `2^32 - 1`. Пропущенные пустые
строки входного TSV не получают идентификаторов. Повторяющиеся URL не
объединяются: каждая непустая запись корпуса — отдельный документ.

## Каталог секций: по 32 байта

| Смещение внутри записи | Байты | Поле |
|---:|---:|---|
| 0 | 4 | Тип секции |
| 4 | 4 | Обязательные флаги (`0`) |
| 8 | 8 | Абсолютное смещение начала секции |
| 16 | 8 | Размер секции в байтах |
| 24 | 8 | Число элементов секции |

Типы: `1` — документы, `2` — словарь, `3` — списки документов,
`4` — статистика, `5` — время индексации. Текущая запись размещает их в этом порядке.
Первая секция начинается с байта `192` при четырёх секциях или `224` при пяти.
Читатель находит секции по типу.
Записи не содержат выравнивающих байтов.

## Секция 1: прямой индекс

Число элементов равно D. Документы записаны последовательно:

| Смещение внутри записи | Байты | Поле |
|---:|---:|---|
| 0 | 4 | Длина заголовка T в байтах |
| 4 | 4 | Длина URL U в байтах |
| 8 | T | Заголовок UTF-8 |
| 8 + T | U | URL UTF-8 |

Размер записи: `8 + T + U`. Заголовок и URL непустые. Текст статьи после
построения индекса не сохраняется: для булева поиска достаточно присутствия
терма, а для выдачи — заголовка и URL.

## Секция 2: словарь обратного индекса

Число элементов равно V. Термы идут строго по возрастанию UTF-8 строк
(лексикографическое сравнение байтов):

| Смещение внутри записи | Байты | Поле |
|---:|---:|---|
| 0 | 4 | Длина терма L в байтах |
| 4 | 4 | Резерв (`0`) |
| 8 | 8 | Номер первого элемента списка в секции 3 |
| 16 | 8 | Число документов с термом, df |
| 24 | L | Нормализованный терм UTF-8 |

Размер записи: `24 + L`. Индекс первого элемента измеряется в элементах
`uint32`, а не в байтах. Списки размещаются подряд: первый начинается с 0,
следующий сразу после предыдущего. Пустых списков и повторяющихся термов нет.

## Секция 3: списки документов

Число элементов P равно сумме df всех термов. Каждый элемент — 4-байтовый
DocId. Каждый список строго возрастающий, без повторов; DocId меньше D.
Байтовое смещение списка: `section3.offset + 4 * first`.
Размер секции равен `4 * P`. Частоты, позиции и сжатие не используются.

## Секция 4: статистика, 32 байта

Число элементов равно 1.

| Смещение | Байты | Поле |
|---:|---:|---|
| 0 | 8 | Сумма UTF-8 байтов заголовков и текстов статей |
| 8 | 8 | Количество токенов до удаления повторов |
| 16 | 8 | Сумма длин всех токенов в Unicode-кодовых точках |
| 24 | 8 | Сумма длин уникальных термов в Unicode-кодовых точках |

URL, TSV-разделители, escape-последовательности и переводы строк записей не
учитываются в размере индексируемого текста. Заголовок и текст токенизируются
отдельно, поэтому их граничные слова не склеиваются. Средняя длина терма =
последнее поле / V; средняя длина токена = третье поле / второе поле.
Для пустого набора среднее в интерфейсе принимается равным нулю.

## Секция 5 — время индексации, 16 байт

Секция добавлена в версии 1.1. Она содержит одну запись и передаёт длительности
в наносекундах как два `uint64`.

| Смещение | Байты | Поле |
|---:|---:|---|
| 0 | 8 | Построение индекса в памяти |
| 8 | 8 | Расчёт размещения, запись и сброс потокового буфера файла |

`boolean_index` измеряет построение через `steady_clock` и передаёт длительность
в `IndexSaver::Save`. После записи и `flush` saver измеряет запись, обновляет
эту секцию и закрывает поток. Запись самого итогового замера и закрытие потока
в длительность не входят.

Общее время — сумма двух длительностей. Время на документ — общее время,
делённое на D, время на КиБ — общее время, делённое на `text_bytes / 1024`.
API дополнительно вычисляет документов/с и КиБ/с. Число термов берётся из словаря,
средняя длина — `term_characters / V`. Все показатели видны в `GET /api/stats`.

Индексы версии 1.0 загружаются с неизвестным временем индексации.
Для времён и скоростей API возвращает `null`, интерфейс предлагает пересобрать
индекс. Секции 1–4 сохраняют прежнее представление. Старый читатель пропускает
неизвестную ему секцию 5.

## Расширение и проверка

Новая необязательная информация (позиции, частоты, дополнительные поля
документа) может добавляться отдельной секцией с новым типом и увеличением
minor-версии. Неизвестные секции с нулевыми обязательными флагами пропускаются.
Размер заголовка может увеличиваться; текущий читатель использует известные
первые 64 байта. Изменение смысла существующих полей требует новой major-версии.
Неизвестная major-версия и ненулевые обязательные флаги отклоняются.
Текущий читатель допускает до 1024 секций.

Проверяются сигнатура, версия, точный размер файла, границы и отсутствие
перекрытий секций, уникальность типов, обязательные секции, размеры/счётчики,
UTF-8, каноничность и порядок термов, непрерывность диапазонов списков,
порядок и границы DocId, согласованность базовой статистики. Контрольной суммы
нет: изменение байтов на другие структурно допустимые данные не обязательно
обнаружится. `IndexSaver::Save()` открывает целевой файл напрямую через
`std::ofstream(path, std::ios::binary)`, записывает поля и проверяет состояние
потока после закрытия. Существующее содержимое файла перезаписывается;
при ошибке записи или прерывании работы может остаться неполный файл.

## Внутреннее представление и сортировка

Документ после токенизации представлен последовательностью нормализованных
строк. Поддерживаются ASCII-латиница, русские буквы А–Я/а–я, Ё/ё и цифры 0–9;
последовательности этих символов образуют токены. Остальные Unicode-символы
служат разделителями. Регистр латиницы и русского алфавита понижается; ё и е
остаются разными буквами. Стемминг и удаление стоп-слов не выполняются.
Некорректный UTF-8 отклоняется. Длины считаются по кодовым точкам, а не байтам;
для поддерживаемого алфавита это соответствует числу букв и цифр.

В ходе построения для каждого документа создаётся плоский массив пар
`(терм, DocId)` для токенов заголовка и статьи. Собственная итеративная
сортировка слиянием сортирует этот небольшой массив; повторы внутри документа
удаляются до добавления в общий массив. Поэтому глобальный массив содержит
P пар присутствия терма в документе, а не все N вхождений токенов.
Исходные частоты токенов сохраняются в статистике. Затем тот же алгоритм
сортирует глобальный массив по терму, затем по DocId. Линейный проход
формирует словарь и отсортированные списки документов.
Используются только строки и динамические массивы (`std::vector`); готовых
хеш-таблиц, деревьев, `std::sort` и готовых алгоритмов множеств нет.

Сортировка слиянием даёт гарантированные `O(K log K)` сравнений для массива
из K элементов и стабильность,
последовательно читает массивы и подходит для последующего перехода к внешней
сортировке. Сравнение строк дополнительно зависит от длины общего префикса.
Общая оценка — `O(Σ n_d log n_d + P log P)`, где n_d — число токенов
документа. Недостатки: второй массив из P пар, хранение одинаковых строк
для разных документов и отсутствие потоковой записи промежуточных серий.
Предварительное удаление повторов сокращает память глобальной сортировки;
его выигрыш зависит от повторяемости слов в статьях.
Строки при слиянии перемещаются, а не копируются. В этой реализации весь
массив всех пар присутствия термов помещается в память; это учебная in-memory индексация, не
готовая внешняя сортировка.

После построения остаются массив документов и отсортированный массив
`Term { строка, массив DocId }`. Поиск терма выполняется собственным двоичным
поиском за `O(log V)` сравнений. При чтении документов и термов загрузчик
временно хранит байты текущей секции. Списки документов читаются из файла.
